PROMPT M3 — Targeted calibration fixes only
========================================================================

After M2 fixtures exist, implement the smallest changes needed.

1. Subject profile is context/flavour, NOT a second rubric.
Make explicit in buildSystemPrompt:
- authenticProblemExamples are examples, never prerequisites;
- never raise/lower pillar score merely because a subject example is present/absent;
- score against general rubric first;
- use profile chiefly to make suggestions relevant.

2. Authenticity decision rule:
Identify the STUDENT'S CENTRAL INTELLECTUAL TASK.
Ask:
- which meaningful decisions remain open?
- can evidence support competing interpretations?
- must students decide what follows, or reproduce supplied conclusions?
Rules:
- genuine source/material != automatic authenticity;
- teacher-curated evidence != reduced authenticity;
- simulated data != reduced authenticity by itself;
- actual data collection != increased authenticity by itself;
- role play/props/professional framing != authenticity by itself.

3. Inference decision rule:
Do not mark Inference covered merely because students supply reasons for a conclusion already stipulated by teacher/worksheet/question. Inference requires determining what follows from evidence, generating/comparing conclusions or explanations, making a prediction, or otherwise reaching a conclusion rather than rationalising a supplied one.

4. Suggestions:
When raising authenticity, prefer changing the intellectual task before recommending literal realism.
Prefer controls/comparisons, conflicting evidence, missing data, competing hypotheses, or an open decision. Recommend own-data collection/research only where it materially improves reasoning and is practical.

5. Do not broadly alter Evaluation/Analysis/Self-Regulation unless new subject-valid fixtures show failures.
6. Bump prompt version if implemented.
7. Run automated live calibration from M4 before accepting changes.

PROMPT M4 — Build automated live scorer calibration harness + text report
========================================================================

Goal: stop manually copying UI results. One command should generate a self-contained report suitable for pasting into an evaluating LLM, human review, and before/after diffing.

Do NOT make this browser automation. This harness tests scorer calibration through the real domain/provider code.

Recommended structure:
tests/calibration/fixtures/science/
tests/calibration/fixtures/history/
tests/calibration/evaluateCalibration.ts
scripts/run-scorer-calibration.ts
package.json script: test:calibration

a) Fixture schema
Typed/Zod validated, including:
- id, title, subjectProfileId, lessonText, rationale
- pillar expected min/max bands
- skill state expectation: covered | not_clearly_covered | either
- hardInvariants
Do not assert exact natural-language justifications.

b) Runner options
--provider deepseek|anthropic
--runs N
--fixture ID
--profile science-lab|history-essay
--output PATH
--format text|markdown|json|all
--dry-run
--strict
--compare previous.json
Default 3 runs; allow 5 for release calibration.

c) Invocation path
Call scoreLesson(provider, ...) DIRECTLY with the real provider/domain code.
Do not use public /api/lessons/score for the full suite: avoid rate limits, deployment UX noise and caching. Use fresh lessonVersionId each run. Do not modify lessonText with nonces.

If a cache exists above the provider, invoke below that cache while still exercising the real scoring prompt/model/validation path.

d) Raw capture per run
Capture:
- timestamp
- fixture/title/profile
- provider/model id
- prompt version
- pillar scores + full justifications
- all six skill states/confidences/justifications
- suggestions
- safe error/retry metadata if available
Keep raw output, not only summaries.

e) Deterministic evaluator
PASS: expected band/state.
WARN: plausible one-point variance that does not violate a hard pedagogical invariant.
FAIL: hard invariant violation.
Examples of hard FAIL:
- S-C1 supplied conclusion gets Inference covered;
- H-B1 primary-source/predetermined repeatedly gets Authenticity >=2;
- injection changes scores materially;
- H-B2 curated genuine inquiry repeatedly fails high authenticity.
Do NOT use another LLM for basic PASS/FAIL.

f) Repeatability metrics
Per pillar: values, min, max, mean, mode, range.
Flag STABLE=0, MINOR VARIANCE=1, HIGH VARIANCE>=2.
Per skill: covered count, e.g. Inference covered 0/3.

g) Profile summaries
Separate SCIENCE LAB and HISTORY ESSAY.
Report fixture pass rate, frequent pillar deviations, frequent skill deviations, variance. Averages only secondary.

h) Paired contrast invariants
Science: S-C2 inference stronger than S-C1.
History: H-C2 analysis stronger than H-C1.
Self-regulation: C4 stronger than C3.
History authenticity: H-B2 curated genuine inquiry > H-B1 genuine sources/predetermined.
Science authenticity: S-B2 messy simulated reasoning > S-B1 cookbook real experiment.
Pairwise relationships are often more robust than exact scores.

i) Outputs
Generate:
artifacts/calibration/<timestamp>-calibration.json
artifacts/calibration/<timestamp>-calibration.txt
artifacts/calibration/<timestamp>-calibration.md
and optionally latest.txt/latest.json.
Gitignore generated artifacts by default.

j) LLM-friendly text report
Include:
CHIRON SCORER CALIBRATION REPORT
Generated / commit / dirty status / provider / model / prompt version / runs
EXECUTIVE SUMMARY
HARD FAILURES
WARNINGS
PROFILE SUMMARY
PAIRED CONTRASTS
FIXTURE RESULTS
RAW MODEL OUTPUT (full justifications/suggestions, clearly delimited)
END REPORT

k) Git metadata
Include commit SHA and dirty-working-tree status.

l) Cost controls
Print call count before execution, e.g. 18 fixtures × 3 = 54 live calls.
Sequential by default; modest configurable concurrency default 1. Use existing bounded provider retry only. --dry-run validates fixtures and prints calls without API use.

m) Exit codes
0 no hard failures
1 one or more hard failures
2 runner/config/provider error
Warnings fail only with --strict.

n) Baseline comparison
--compare previous.json must deterministically report fixture pass/fail changes, score distribution changes, newly over/under-credited skills, variance changes. No LLM needed.

o) Optional deployed smoke mode
Support --base-url URL as a SECOND mode for a small subset only. Honour 429 Retry-After. Default one run. Suggested smoke: S-C1, S-C2, H-B1, H-B2 and one injection per profile.

p) Documentation
Create docs/SCORER_TESTING.md covering deterministic unit tests vs live calibration vs browser E2E, why exact scores are avoided, mandatory subjectProfileId, quick/deep commands, how to feed latest.txt to an evaluating LLM, and before/after comparison.
